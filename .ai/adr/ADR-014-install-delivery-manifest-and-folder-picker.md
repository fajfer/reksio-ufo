# ADR-014: Ship from a manifest or a folder picker

- **Status:** Accepted (retroactive)
- **Date:** 2026-10-21
- **Evidence:** `91fa1e2` (dev server and folder input), `aaa03f3` (`game-manifest` for static hosting), `4f49613` (preview server), `4d9f035` (iOS fallback); `src/engine/fs.ts`, `tools/game-manifest.ts`.
- **Supersedes:** none

## Context

Static hosting cannot list a directory, and the game install is not part of the repository. A player may either run a server that exposes their install at `./game/`, or pick the folder locally. iOS has no `webkitdirectory`, so the picker is not universally available.

## Decision

Support two delivery modes behind the same `GameFS`: (1) an HTTP install discovered through `./game/manifest.json`, a JSON array of install-relative paths, generated by the dev/preview server on the fly or by `npm run game-manifest` for static hosting; (2) a folder picked with `<input webkitdirectory>`, with the picked root stripped. The app boots when `DANE/Application.def` exists. The folder picker is the fallback; on iOS it is hidden and the served install or offline download is the only path. No backend and no directory listing are required.

## Consequences

- MUST keep the game manifest a JSON array of install-relative paths. It is not the PWA `manifest.webmanifest`; the boot code must reject the wrong shape with a clear message.
- MUST keep the manifest generator walking the whole install and writing every file, including nested directories.
- MUST cache the manifest itself for offline boot; it is not part of its own file list.
- MUST keep boot detection on `DANE/Application.def`, not on a folder name or a platform-specific path.
- A new delivery mode MUST implement `GameFS` (ADR-007) rather than add branches to the engine.
- MUST NOT require a server, a build-time game copy, or a directory listing.
